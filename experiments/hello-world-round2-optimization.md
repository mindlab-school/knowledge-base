## 1. Что чинили (по итогам раунда 1)

Раунд 1 показал: заземление идеально, но агент **чрезмерно осторожен** — 34/94 отвечаемых вопроса он «зарубал». Три причины:
1. **Цены/контакты → пустой блок фактов.** Правило «бери цены/пакеты/расписание/контакты из блока АКТУАЛЬНЫЕ ФАКТЫ **без поиска**» приводило к отказу, когда блок фактов пуст, — вместо поиска по документам.
2. **Обобщённое «школа/организация» → «уточните, о какой школе речь».**
3. **Отказ до поиска** и путаница фактов (методику взял из профиля преподавателя).

## 2. Что изменено в системе

### 2.1. Дефект №2: краш `HTTP 500` на строковом `filters`

Оптимизация (более активный вызов инструментов) вскрыла второй дефект: когда модель передавала аргумент `filters` **строкой** вместо объекта, `build_document_where` падал с `AttributeError: 'str' object has no attribute 'items'` → `HTTP 500`, обрывая весь запрос.

**Исправление:** `build_document_where` теперь безопасно игнорирует не-словарь; в слое инструментов добавлена коэрция `filters` (строка-JSON → объект, мусор → отбрасывается). Покрыто юнит-тестами (`test_structured_filters`, `test_tool_filters`). Стенд-харнесс тоже упрочнён: сбой одного вопроса больше не роняет весь прогон.

### 2.2. Новый системный промпт: «сначала ИЩИ — потом отвечай»

`src/kb/agent/prompts.py` полностью переписан (доменно-нейтрально). Ключевые изменения:
- **Поиск — действие по умолчанию.** Отказ `«в базе знаний этого нет»` допустим только ПОСЛЕ реального поиска. Пустой/неполный блок фактов — **не** повод для отказа: цены и контакты почти всегда есть в документах.
- **Запрет переспрашивать про организацию.** «Школа», «компания», «мы», «наши» — всегда данная организация; уточнение — только при настоящей неоднозначности внутри базы.
- **Точность фактов.** Факт бери из профильного документа; не подменяй методику организации фразой из личного профиля сотрудника; при сомнении открывай документ целиком (`get_document`).
- Явная маршрутизация инструментов и мини-примеры «как НЕ надо → как надо».

## 3. Стенд для тестирования: `scripts/eval_hw.py`

Чтобы легко прогонять систему заново, добавлен переиспользуемый харнесс (вызывает агентный цикл **в процессе**, без HTTP-сервера) и зафиксированные данные:
- `tests/fixtures/hw_corpus/` — снапшот 13 документов сайта + `manifest.json` (URL/заголовки).
- `tests/fixtures/hw_questions.json` — 100 вопросов + эталонные ответы + флаг `out_of_corpus`.
- `scripts/eval_hw.py` — команды `ingest` (сброс БД + загрузка снапшота), `run` (задать вопросы), `report`, `all --judge` (+ LLM-оценка). Не пишет чат-историю, поэтому не тратит бюджет спенд-гарда.

```bash
make eval-ingest              # заново загрузить данные (reset + ingest снапшота)
make eval-run ARGS="--judge"  # заново задать 100 вопросов, с оценкой
make eval                      # всё сразу: ingest + run + LLM-graded report
uv run python scripts/eval_hw.py run --only 31,33,47   # подмножество
```
Данные фиксированы, поэтому прогоны **сравнимы** — меняется только система, а не корпус.

## 4. Оптимизация промпта параллельными агентами

«Довести до идеала» сделано эмпирическим турниром, а не на глаз:
1. **Генерация.** 4 параллельных агента предложили 4 разных переписанных промпта (стратегии: директивная, по-правилам, дерево решений, с мини-примерами) + 1 мой вариант = **5 кандидатов**.
2. **Турнир.** Каждый кандидат прогнан на репрезентативном подмножестве из 50 вопросов (все провалы раунда 1 + контрольные + все внекорпусные) с LLM-оценкой. Ранжирование по составной метрике (верно ↑, отказы ↓, галлюцинации на внекорпусных — жёсткий штраф).
3. **Финал.** Победитель прогнан на всех 100; синтез-вариант не смог быть дооценён — на OpenRouter закончились кредиты (см. ниже), поэтому итог зафиксирован по победителю турнира.

**Ранжирование турнира** (подмножество 50 вопросов, оценка дешёвым судьёй — для относительного сравнения):

| Кандидат | Стратегия | Балл | Верно/44 | Отказы | Галлюц. на внекорп. |
|---|---|---:|---:|---:|---:|
| E_agent | мини-примеры ← победитель | 65.0 | 32 | 1 | 0 |
| C_agent | дерево решений | 58.0 | 31 | 1 | 0 |
| A_mine | мой вариант | 54.0 | 26 | 2 | 0 |
| B_agent | директивный | 53.0 | 30 | 2 | 0 |
| D_agent | по-правилам | 38.0 | 26 | 3 | 0 |

Победил **E (стратегия «мини-примеры»)**: максимум верных, минимум отказов, 0 галлюцинаций на внекорпусных. Его текст — в `src/kb/agent/prompts.py`.

## 6. Ограничение прогона

В ходе оптимизации на аккаунте OpenRouter **закончились кредиты** (`402 Insufficient credits`). К этому моменту победитель уже был определён турниром и полностью прогнан на 100 вопросах, поэтому итог достоверен; недоделаны лишь: доводочный run-off синтез-варианта и авто-оценка сильным LLM-судьёй (заменена ручной проверкой по эталону). Для повторного прогона пополните кредиты и запустите `make eval`.

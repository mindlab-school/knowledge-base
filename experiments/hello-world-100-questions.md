## 1. Что и зачем тестировали

KB Agent отвечает на вопросы **строго по загруженным документам** и обязан отказываться (`«в базе знаний этого нет»`), если ответа в корпусе нет. В базу загружены 13 страниц публичного сайта детской онлайн-школы «Hello World» (`hwschool.online`): главная, «О школе», «Контакты», карта сайта, страницы курсов (Python, Scratch, Roblox, создание сайтов, Unity, ментальная арифметика), репетиторы и «Сведения об образовательной организации».

Цель эксперимента — прогнать 100 заранее заготовленных вопросов (10 тематических блоков) и задокументировать, **что и как отвечает система**: точность, заземление, поведение на отказах и на заведомо отсутствующих данных.

## 2. Методология

- **Канал:** HTTP `POST /chat` к запущенному бэкенду (`telegram_id` из белого списка).
- **Изоляция:** перед каждым вопросом — `POST /reset`, поэтому каждый вопрос отвечается в **чистом контексте** (без истории предыдущих). Это делает результат воспроизводимым и по-вопросно интерпретируемым.
- **Дословность:** вопросы заданы ровно так, как в задании (никаких переформулировок «под систему»).
- **Последовательность:** вопросы задавались по очереди, один за другим.
- **Оценка:** для каждого вопроса вручную построен эталонный ответ из исходных документов; ответы системы оценены по 7-балльной шкале вердиктов (см. TL;DR) панелью из 9 независимых оценщиков (по одному на блок) с последующей ручной проверкой спорных случаев.
- **Замечание о недетерминированности:** ответы LLM стохастичны. Каждый вопрос задан **один раз**; отдельные категории (особенно «отказ»/«уточнение» на пограничных формулировках) могут меняться от прогона к прогону.

## 3. Обнаруженный и исправленный дефект: `HTTP 500` на фильтре по дате

**Симптом.** Во время прогона вопросы про даты/историю (например, №12 «в какой программе школа участвовала в конце 2018 года?») возвращали `HTTP 500`.

**Первопричина.** В `src/kb/search/structured.py` функция `build_document_where` для фильтров `created_before`/`created_after` (и атрибутных `<attr>_before`/`_after`) подставляла ISO-строку даты прямо в параметр запроса к колонке `TIMESTAMPTZ`:

```
d.created_at < $1        -- $1 = '2020-01-01' (str)
```
`asyncpg` определяет тип параметра как `date`/`timestamptz` и требует объект `datetime.date`/`datetime`, а не строку — отсюда `asyncpg.exceptions.DataError: expected a datetime.date ... got 'str'`. Дефект не ловился, потому что юнит-тест проверял только сгенерированную SQL-строку и никогда не исполнял запрос против БД (атрибутные фильтры с `::date` были сломаны так же, но их путь не исполнялся в тестах).

**Исправление.** ISO-строки парсятся в `datetime.date` в Python, а колонка приводится к `::date` (`d.created_at::date < $1`); неразбираемые даты пропускаются (предикат не добавляется), чтобы не ронять весь запрос. Добавлены: юнит-тест на пропуск неразбираемой даты и **интеграционный тест** (`tests/integration/test_structured_dates.py`), который исполняет фильтры по дате против реального pgvector.

**Эффект.** До исправления: №12 и №17 → `HTTP 500`. После: оба отвечаются корректно (№12 → «Бизнес для меня», №17 → курсы английского 7–12 лет).

## 5. Ключевые наблюдения

1. **Заземление работает идеально.** Ни одной галлюцинации на 100 вопросов; все 6 внекорпусных вопросов (курс китайского, зарплаты, офис в Казани, курс кибербезопасности, набор в 2026, основатель Roblox Corp.) корректно отклонены. Это — главная цель системы, и она выполняется.

2. **Чрезмерная осторожность — основная слабость.** 34 из 94 отвечаемых вопросов система «зарубила»: **21 ложных отказов** и **13 лишних запросов уточнения**, хотя ответ был в документах. Два повторяющихся паттерна:

   - **Цены → «АКТУАЛЬНЫЕ ФАКТЫ».** Базовые цены абонементов (№31–35) система отклоняет со словами «…могла бы быть в разделе АКТУАЛЬНЫЕ ФАКТЫ, но там этого нет», **не выполняя поиск по документам** — хотя вся тарифная сетка есть в корпусе. При этом смежные ценовые вопросы (№36–46, 48) отвечаются верно — поведение непоследовательно.

   - **Обобщённая формулировка «школа» → «уточните, о какой школе речь».** Вопросы вида «сколько у школы преподавателей?», «когда родилась школа?», «какое полное наименование юрлица?» (№3, 5, 11, 15, 18, 19, 20, 85, 86, 88) часто получают запрос уточнения: системный промпт позиционирует агента как «универсальную корпоративную» базу, и слово «школа» читается как неоднозначный ключ, а не как предмет всей базы.

3. **Когда отвечает — точность высокая.** Из 60 содержательных ответов 53 полностью верны (88%), с корректными ссылками на документы-источники. Всего 2 фактические ошибки:

   - №10 (методика): система назвала методикой школы «исследовательский подход», взяв фразу из **личного профиля преподавателя** Р. Мустафина, вместо реальной методики «Step by step».

   - №53 (возраст Unity): «с 12 лет» вместо «10+» по корпусу.

4. **Исходные документы противоречивы — и это видно в ответах.** В корпусе расходятся: возраст школы (6–17 vs 7–17), число учеников (31 000+ / 19 000 выпускников / 10 000 / 6000+), опыт П. Ершова (5+ vs 6 лет). На таких вопросах (№8, 9) система даёт «частично» — ожидаемо для неоднозначного источника.

5. **Исправленный баг разблокировал целый блок.** До правки вопросы по датам падали в `500`; после — блок «История» отвечается (7 из 8 верно).

## 7. Как воспроизвести

```bash
# 1. БД (уже поднята как контейнер kb-hw-db на :5433) и миграции
make up && make migrate
# 2. Пользователь в белом списке
uv run python -m kb.cli.admin add-user <telegram_id> "Experiment Runner"
# 3. Бэкенд
make run-api
# 4. По каждому вопросу: POST /reset -> POST /chat {telegram_id, text}
#    (100 вопросов из этого файла, каждый в чистом контексте)
```
Артефакты прогона (JSON с ответами, латентностью и вердиктами) сохранены во временной рабочей директории сессии и не коммитятся в репозиторий.
